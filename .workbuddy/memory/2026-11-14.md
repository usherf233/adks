
## Graph 编排落地（v0.3）

用户提出要做 Graph 类型。**设计文档 §6 原判"不做 graph"，理由是错的**——ADK Go v2.7.1 的 `workflow` 包就是 graph 引擎，`workflowagent.New(Config{Edges})` 直接返回 `agent.Agent`，graph 是 `[]workflow.Edge` 纯数据，天然适配配置生成。已勘误修正 §6 与边界行。

**实现**
- `manifest/`：`spec.mode: llm|graph` + `spec.graph.{nodes,edges}`；节点种类 `agent|tool|route|join|subgraph`；`manifest/graph_validate.go` 做拓扑校验（环、可达、START 出度、入边、死分支、route 标签一致性）
- `kit/graph.go`：`graphBuilder` 编译 manifest → `workflowagent.New`；`routeNode` 自研节点（嵌入 `workflow.BaseNode`，实现 Run）
- `internal/api/graph.go`：`GET /api/projects/{slug}/graph` 拓扑端点
- 前端：编排模式卡片 + 节点/边表单编辑 + **只读分层拓扑图**

**关键事实（踩过的坑，必须记得）**
- **`AgentNode` 不设 `Event.Routes`** → LLM 输出无法直接决定分支，条件分支必须插 `route` 节点。这是 graph 配置化唯一的硬缺口，要写进产物边界
- **模型侧 builtin 工具做不了 tool 节点**（`google_search`/`url_context` 是 geminitool，不是 runnableTool）→ `workflow.NewNamedToolNode` 会报 "not directly runnable"。校验层已禁止
- **`SubAgents` 必须注册**所有被包进图的 agent，否则 runner 每轮打 `Event from an unknown agent`
- `NewNamedToolNode` 返回 `(*ToolNode, error)`，不是单值
- 没有 END sentinel，**无出边的节点即终点**
- `graph` 模式与 `tools.toolSearch` 互斥（两者都在回答"工具太多"，同时开会互相抵消）

**前端两个真 bug（不是脚本问题）**
- 改边的 select 只 `markDirty` 不重渲染 → 拓扑图停留在旧数据。修法：`spec.graph.` 前缀的改动单独 `refreshTopology()`，不重建表单（否则丢焦点）
- `.mode-card input { display:none }` 让 radio 跳出 tab 顺序，键盘用户切不了模式 → 改视觉隐藏 + `:focus-within`

**验证**
- 端到端条件路由实测通过：`TestGraphRoutesConditionally` 用 stub model，"我要退款"走 refund 分支、"查订单"走 other 分支，互不串
- 浏览器实测：建项目 → 切 graph → 加节点/边 → 拓扑图实时更新 → 校验通过 → 保存 → YAML 正确 → **导出工程 go build + go vet 全绿**
- 留了示例项目「客服工单分流」（`support-router`，5 节点 7 边，零 issue）

**仍然不做**：拖拽画布（YAML + 表单 + 只读拓扑图已够）；子图的图形化编辑（YAML 兜底）。

**踩过的坑（必须记得）**
- **外层中间件拿不到 `r.PathValue("slug")`**：ServeMux 匹配后才填充 PathValue，而 guard 包在 mux 外面 → 校验曾完全失效（测试返回 200 loadError 才发现）。修法：`requestSlug()` 从 `r.URL.EscapedPath()` 切段并 `url.PathUnescape`，`slugOf()` 也统一走它。
- `functiontool.Run` 会把结果 map 过一遍 JSON，`resp.StatusCode` 的 int 变成 float64；断言状态码要用 `asInt()`。
- `schemaFromParams` 的 `PropertyOrder` **必须排序**（`TestSchemaFromParamsIsStable` 断言 `alpha` 在首位），注释里"manifest 控制顺序"是错的，已把注释改为如实描述。

**关键实现决策**
- 鉴权/CSRF：`guard` 统一校验 slug 白名单、`Origin`/`Sec-Fetch-Site`、POST/PUT 强制 `application/json`；DELETE 豁免 Content-Type（本身非 safelisted method）；token 用 `subtle.ConstantTimeCompare`；`-host ""` 归化为 `127.0.0.1`。
- Store：所有读写方法都 `checkSlug`；`Create` 用 `os.Mkdir` 原子占位；`Rollback` 与 `Save` 共用同一把锁（新增 `saveLocked`）；`reindex` 加 `indexMu`；快照名精确到纳秒。
